# AGENTS.md (apps/server)

NestJS backend application. Read the root `AGENTS.md` first; this file adds server-specific rules.

---

## 1. Stack

1.1 NestJS 11, TypeScript.
1.2 Database: PostgreSQL via `node-postgres` with **Drizzle ORM v1**.
1.3 Auth: `better-auth`. Mounted via `AuthController` at `/api/auth/*`.
1.4 Validation: Zod schemas from `@workspace/validation` applied via `ZodValidationPipe`.
1.5 Tests: **Vitest** + `@nestjs/testing` with `unplugin-swc`.
1.6 Build: `@nestjs/cli` (`pnpm build` outputs `dist/main.js`). Dev: `nest start --watch`.
1.7 Linting and formatting are done from the repo root (Oxlint + Prettier).

## 3. Deviations from next-express

1. **NestJS Modules & Controllers instead of Express Routers & Handler Functions**:
   - _Rule Changed_: Express procedural routing (`app.use("/api/test", testRoutes)`) and controller functions `(req, res, next)`.
   - _Reason_: NestJS is built on structured modules, dependency injection, and decorator-driven controllers (`@Controller`, `@Get`, `@Param`).
   - _Replacement_: `TestController` in `src/modules/test/test.controller.ts` with explicit HTTP route decorators.

2. **NestJS Dependency Injection & Layering**:
   - _Rule Changed_: Direct module imports of functions (`getTestService`, `findTestByIdQuery`).
   - _Reason_: NestJS achieves loose coupling, testability, and inversion of control via constructor dependency injection.
   - _Replacement_: `@Injectable()` `TestService` and `TestQuery`, registered in `TestModule`. Database injected via `@Inject(DRIZZLE_DB)`.

3. **Validation Pipes & Exception Filters**:
   - _Rule Changed_: Express error middleware and manual `AppError` class.
   - _Reason_: NestJS provides native HTTP exception hierarchy (`BadRequestException`, `NotFoundException`) and lifecycle hooks for validation and exceptions.
   - _Replacement_: `ZodValidationPipe` validating DTOs with `@workspace/validation` schemas, and `HttpExceptionFilter` formatting error responses.

4. **Build & Dev Tooling**:
   - _Rule Changed_: `tsup` for compilation.
   - _Reason_: NestJS requires decorator metadata emission (`emitDecoratorMetadata`), for which `@nestjs/cli` (`nest build`) is the official standard.
   - _Replacement_: `nest build` outputting `dist/main.js`, and `nest start --watch` for development.

5. **Testing Harness**:
   - _Rule Changed_: Raw Supertest with Express app.
   - _Reason_: NestJS testing utilizes `@nestjs/testing` (`Test.createTestingModule`) for unit and integration tests with mocked providers.
   - _Replacement_: `@nestjs/testing` with Vitest and `unplugin-swc`.
