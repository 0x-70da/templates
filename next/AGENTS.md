# AGENTS.md (Next.js Full-Stack)

This is a standalone full-stack Next.js application built with Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS v4, Drizzle ORM v1, PostgreSQL, Better Auth, and shadcn Base UI.

> How to extend this file: add a new numbered section at the bottom, or a new numbered rule inside the matching section. Keep each rule short and actionable.

---

## 1. Stack

1.1 Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS v4.
1.2 Database: PostgreSQL via `node-postgres` with **Drizzle ORM v1**.
1.3 Auth: `better-auth` with Drizzle adapter and admin plugin, mounted at `app/api/auth/[...all]/route.ts`.
1.4 Server Actions: Mutation and query actions in `actions/<domain>/` with `server-only`.
1.5 Forms: `react-hook-form` with `@hookform/resolvers/zod`.
1.6 Components: **shadcn with Base UI** (`@base-ui/react`), installed locally in `components/ui`.
1.7 Testing: **Vitest** + Testing Library (`jsdom` for unit tests, `node` for integration tests).
1.8 Tooling: Oxlint (type-aware) + Prettier + Husky + lint-staged.

---

## 2. Deviations from next-express

2.1 **Single Full-Stack App:** No Turborepo or `@workspace/*` packages.

- Contract types live in `types/`, Zod schemas in `validation/`.
  2.2 **Server Actions Architecture:** Instead of an Express HTTP server, server-side data mutations use Next.js **Server Actions** in `actions/<domain>/`.
- Flow: Server Component (or Action) -> Service (`services/<domain>/`) -> Query (`queries/<domain>/`) -> Database (`db/`).
  2.3 **Cache Revalidation:** Cache invalidation happens inside Server Actions using `revalidatePath` or `revalidateTag`.

│   ├── page.tsx

├── actions/

├── services/
│   └── <domain>/                  # business logic functions (server-only)

3.1 Route folders in `app/` contain **only** `page.tsx`, `layout.tsx`, `error.tsx`, `not-found.tsx`, and `sections/`.
3.2 All components, actions, services, queries, stores, types, and schemas live in root-level domain folders.
3.3 **One unit per file:** one action, service, query, component, store, or schema per file.

---

## 4. Server Layering & Request Flow

```
app/<route>/sections/XYSection.tsx -> services/<domain>/ -> queries/<domain>/ -> db
form submit -> actions/<domain>/ -> services/<domain>/ -> queries/<domain>/ -> db
```

4.1 **Action**: handles client payload, validates with zod from `validation/`, calls service, and triggers `revalidatePath` / `revalidateTag`.
4.2 **Service**: business logic. Isolated helper functions at the bottom of the file (no spaghetti code). Throws `AppError`.
4.3 **Query**: only layer that imports `db`. Applies `nullToUndefined` on rows.

## 5. Tooling & Commands

| Command              | What it does                                |
| -------------------- | ------------------------------------------- |
| `pnpm install`       | Install dependencies and configure Husky    |
| `pnpm dev`           | Starts Postgres container, then `next dev`  |
| `pnpm build`         | Build production Next.js app (`next build`) |
| `pnpm start`         | Run production build                        |
| `pnpm lint`          | Run type-aware Oxlint                       |
| `pnpm lint:fix`      | Run Oxlint with autofix                     |
| `pnpm lint:ci`       | Run Oxlint with `--deny-warnings`           |
| `pnpm format`        | Run Prettier formatting                     |
| `pnpm format:check`  | Check Prettier formatting                   |
| `pnpm typecheck`     | Run `next typegen && tsc --noEmit`          |
| `pnpm test`          | Run all Vitest tests                        |
| `pnpm test:unit`     | Run unit tests (`test/unit/**`)             |
| `pnpm db:generate`   | Generate Drizzle migrations                 |
| `pnpm db:migrate`    | Apply Drizzle migrations                    |
| `pnpm auth:generate` | Regenerate auth schema from `lib/auth.ts`   |
| `pnpm db:up`         | Start Postgres container                    |
| `pnpm db:down`       | Stop Postgres container                     |
